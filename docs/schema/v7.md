# MotionForge ZIP Schema v7 参考

> 导出/导入的 ZIP 运动包完整字段定义。下游系统按此实现解析即可。
>
> 版本：**schema_version = 7**（当前）
> 源码入口：[ResultPackageExporter.js](../../src/core/ResultPackageExporter.js)
> 数学原理：[HOW-IT-WORKS.md](../../HOW-IT-WORKS.md)
> 历史版本：[v4.md](v4.md)（v4 字段参考，仍适用于所有跨版本共通字段）

---

## ZIP 包结构

```
<name>-motion-package-<timestamp>.zip
├── manifest-<timestamp>.json   # 元信息 + 文件索引 + scene markers metadata
├── model-<timestamp>.glb        # 场景模型（GLTFExporter 序列化，零位态）
├── joints-<timestamp>.json      # FK 关节定义
├── motion-<timestamp>.json      # 全局关键帧 clips + reparent 事件
└── pkf-<timestamp>.json         # PKF 参数化公式（可选）
```

`<timestamp>` = `YYYYMMDD-HHMMSS`，所有文件共享同一时间戳。

## manifest.json

顶层元信息，**必须最先读**（判断 schema 版本 + 找其他文件）。

```json
{
  "schema_version": 7,
  "generator": "MotionForge",
  "exported_at": "2026-04-24T12:34:56.789Z",
  "source": {
    "file_name": "shuangchaxiaoqianyi.fbx",
    "root_name": "Scene",
    "format": "fbx",
    "up_axis": "Z",
    "units_in_meters": 1.0,
    "fps": 30
  },
  "scene_markers": [
    {
      "id": "marker-001",
      "name": "PickupAnchor",
      "type": "pickup",
      "size": { "x": 0.5, "y": 0.5, "z": 0.5 },
      "color": "#22d3ee"
    }
  ],
  "files": {
    "manifest": "manifest-20260424-123456.json",
    "model":    "model-20260424-123456.glb",
    "joints":   "joints-20260424-123456.json",
    "motion":   "motion-20260424-123456.json",
    "pkf":      "pkf-20260424-123456.json"
  }
}
```

### 字段定义

| 字段 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `schema_version` | number | ✅ | Schema 版本号，当前 `7`。读取前先校验 |
| `generator` | string | ✅ | 导出工具名，固定 `"MotionForge"` |
| `exported_at` | string (ISO 8601) | ✅ | 导出时间 |
| `source.file_name` | string | ✅ | 源文件名（如 `"model.fbx"`） |
| `source.root_name` | string \| null | ⚠️ v4+ | 原始场景根节点名（如 FBX 里的 `"Scene"`）。v4 前 ZIP 无此字段 |
| `source.format` | string | ✅ | 源格式：`glb` / `gltf` / `usdz` / `usd` / `fbx` |
| `source.up_axis` | string | ✅ | 约定为 `"Z"`（UI Z-up；Three.js 世界 Y-up，两者由 `mapUiAxisToWorld` 互转） |
| `source.units_in_meters` | number | ✅ | 当前固定 `1.0`（米制） |
| `source.fps` | number | ✅ | 关键帧采样 fps，当前固定 `30` |
| `scene_markers[]` | array | ⚠️ v6+ | 场景标记 metadata（货物占位 / 取货点 / 放货点）。空数组表示无标记 |
| `scene_markers[].id` | string | ✅ v6+ | marker 唯一标识 |
| `scene_markers[].name` | string | ✅ v6+ | marker 对应场景对象的 name（对应 GLB 里的节点） |
| `scene_markers[].type` | string | ✅ v6+ | marker 类型：`pickup` / `drop` / `cargo_placeholder` 等 |
| `scene_markers[].size` | object \| null | — | 尺寸 `{x, y, z}`（米）。cargo_placeholder 必填，其他类型可空 |
| `scene_markers[].color` | string \| null | — | CSS 颜色字符串（UI 高亮用） |
| `files.*` | string | ✅ | 其他 JSON/GLB 文件的相对名（不含路径） |
| `files.pkf` | string \| null | — | 无 PKF 时为 `null`，读取前判空 |

### 关键约束

- `scene_markers` 只存 **metadata**。marker 的 3D 位置已在 `model.glb` 里（作为 sceneRoot 的子对象），按 `name` 关联。
- 导入侧必须在读完 GLB 后，按 marker metadata 的 `name` 去 `sceneRoot.getObjectByName` 找对应的 Three.js 节点。

## joints.json

FK 关节定义数组。每条对应一个可动零件。

```json
{
  "_comment": "FK 关节定义。origin 是关节父级 local 空间；base_transform 是关节零点姿态（parent-local 四元数）。limit_upper/overflow_to 是 v7 引入的双段门架 overflow 机制。",
  "definitions": [
    {
      "id": "a1b2c3d4-...",
      "name": "_CS19110",
      "scene_path": "Scene/双叉小前移/AGV/_CS19110",
      "type": "revolute",
      "axis": "z",
      "role": "叉齿旋转",
      "origin": { "x": 0, "y": 0, "z": 0 },
      "limits": { "min": -180, "max": 180 },
      "limit_upper": null,
      "overflow_to": null,
      "parent_id": "e5f6g7h8-...",
      "parent_name": "AGV",
      "child_id": "a1b2c3d4-...",
      "current_value": 0,
      "base_transform": {
        "tx": -58.74, "ty": -100.70, "tz": -77.85,
        "qx": 0.0, "qy": 0.0, "qz": 0.0, "qw": 1.0
      }
    },
    {
      "id": "mast-inner-...",
      "name": "InnerMast",
      "type": "prismatic",
      "axis": "y",
      "role": "门架升降",
      "limits": { "min": 0, "max": 2.0 },
      "limit_upper": 1.5,
      "overflow_to": "OuterMast",
      "parent_name": "ForkCarriage",
      "child_id": "mast-inner-...",
      "current_value": 0,
      "base_transform": {
        "tx": 0, "ty": 0, "tz": 0,
        "qx": 0, "qy": 0, "qz": 0, "qw": 1
      }
    }
  ]
}
```

### 字段定义

| 字段 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `id` | string (uuid) | ✅ | 关节 uuid（= childId）。**跨 roundtrip 不稳定，仅运行时引用** |
| `name` | string | ✅ | 子对象在场景树里的名字。**跨 roundtrip 稳定**，主键用 |
| `scene_path` | string \| null | — | 从场景根到子对象的路径（用 `/` 分隔），fallback 查找用 |
| `type` | enum | ✅ | `none` / `revolute` / `prismatic` / `fixed`；`none` 会被删除 |
| `axis` | enum | ✅ | `x` / `y` / `z`（UI 坐标系） |
| `role` | string | ✅ v6+ | 语义角色标签（`"叉齿旋转"` `"门架升降"` ...），AI 按此匹配意图 |
| `origin.{x,y,z}` | number | ✅ | 旋转中心（UI 坐标系，关节父级 local 空间）。revolute 必须精确；prismatic 可写 0 |
| `limits.{min,max}` | number | ✅ | 值域（度或米） |
| `limit_upper` | number \| null | ⚠️ v7+ | 双段门架 **第一段上限**。超过后溢出到 `overflow_to`。null = 未启用 |
| `overflow_to` | string \| null | ⚠️ v7+ | 溢出目标关节 **名字**（跨 roundtrip 稳定）。null = 无溢出目标 |
| `parent_id` | string (uuid) \| null | ✅ | 关节父级 uuid。运行时引用，导入时重新解析 |
| `parent_name` | string \| null | ⚠️ v5+ | 关节父级名字。**跨 roundtrip 稳定**，导入时用 |
| `child_id` | string (uuid) | ✅ | 子对象 uuid（通常 = id） |
| `current_value` | number | ✅ | 当前驱动值。v12+ 导出固定 0（GLB 已零位化） |
| `base_transform` | object \| null | ✅ | 关节零点姿态（parent-local） |
| `base_transform.tx/ty/tz` | number | — | 位置（米） |
| `base_transform.qx/qy/qz/qw` | number | ✅ v7+ | 旋转四元数。避免 Euler 万向锁 |
| `base_transform.rx/ry/rz` | number | — | 旋转 Euler（旧数据兼容，v7 前） |

### 关键约束

1. **`name` 是跨 roundtrip 的稳定标识**，导入时按 name 重建 uuid 映射
2. **`parent_name` 必须存在**（v5+）否则链式关节会断，见 [CLAUDE #18](../../CLAUDE.md)
3. **`base_transform` 四元数优先**，有 `qw` 就用四元数，没有才读 Euler（兼容）
4. **`origin` 存 parent-local 不是世界坐标**，见 [CLAUDE #5](../../CLAUDE.md)
5. **`current_value` 必须是 0**（v12+），GLB 已零位烘焙，joints.json 不一致会 double-apply，见 [CLAUDE #30](../../CLAUDE.md)
6. **`limit_upper` + `overflow_to` 配对使用**（v7+）：两者之一为 null 则 overflow 机制未启用。`overflow_to` 存的是目标关节 **名字**，导入时按 name 解析到运行时 uuid。详见 [bugfix #59](../bugfix-log.md)

## motion.json

全局关键帧动画 + reparent 事件。每个 clip 是一段项目级动画。

```json
{
  "_comment": "v5 全局关键帧 + reparent 事件 schema：keyframes[] 驱动 joint_values；reparent_events[] 在指定时间切换对象的 scene graph parent（取货/放货用）。child_name/new_parent_name 用名字跨 roundtrip 稳定。new_parent_name=null 表示挂回世界根。",
  "clips": [
    {
      "clip_name": "default",
      "duration": 10,
      "keyframes": [
        {
          "t": 0.0,
          "joint_values": {
            "_CS19110": 0,
            "_____10": 0
          }
        },
        {
          "t": 5.0,
          "joint_values": {
            "_CS19110": 45,
            "_____10": 1.5
          }
        }
      ],
      "reparent_events": [
        {
          "event_id": "re-001",
          "t": 3.0,
          "child_name": "CargoBox",
          "new_parent_name": "ForkCarriage"
        },
        {
          "event_id": "re-002",
          "t": 7.0,
          "child_name": "CargoBox",
          "new_parent_name": null
        }
      ]
    }
  ]
}
```

### 字段定义

| 字段 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `clips[]` | array | ✅ | 项目级动画片段数组 |
| `clips[].clip_name` | string | ✅ | 片段名（例 `"default"` `"pickup"`） |
| `clips[].duration` | number | ✅ | 时长（秒） |
| `clips[].keyframes[]` | array | ✅ | 关键帧数组（按 `t` 排序） |
| `clips[].keyframes[].t` | number | ✅ | 时间点（秒） |
| `clips[].keyframes[].joint_values` | object | ✅ | 字典 `{关节 name: 值}`。**值单位：revolute=度，prismatic=米** |
| `clips[].reparent_events[]` | array | ⚠️ v5+ | reparent 事件数组（按 `t` 排序）。空数组表示无事件 |
| `clips[].reparent_events[].event_id` | string | ✅ v5+ | 事件唯一标识 |
| `clips[].reparent_events[].t` | number | ✅ v5+ | 触发时间（秒） |
| `clips[].reparent_events[].child_name` | string | ✅ v5+ | 被 reparent 的子对象 name |
| `clips[].reparent_events[].new_parent_name` | string \| null | ✅ v5+ | 新父级对象 name。`null` = 挂回世界根 |

### 关键约束

1. **key 是关节 name，不是 uuid**（跨 roundtrip 稳定）
2. 每个 keyframe 的 `joint_values` 应包含**所有关节**的当前值（全局快照）
3. 插值在运行时按相邻帧线性计算，边界外保持边界值
4. **reparent_events 必须按 `t` 升序**；重播时从 t=0 沿事件列表累积得到目标状态（不是处理 delta），seek 到任意时间都正确。见 [KeyframeManager.applyReparentEventsAtTime](../../src/core/KeyframeManager.js)

## pkf.json（可选）

参数化关键帧公式。有它时可替代 motion.json 的静态关键帧，支持参数调节。模板路径（叉车 / 三向车）生成的 PKF 带 `template_meta`。

```json
{
  "_comment": "参数化关键帧公式：parameters 声明输入参数，steps 定义公式驱动的运动步骤。joint 字段引用 joints.json 的 name。",
  "template_meta": {
    "kind": "threeway",
    "version": 1,
    "params": { "x_axis_threshold": 0.3, "fork_insertion_depth": 0.5 }
  },
  "parameters": [
    {
      "id": "lift_height",
      "type": "number",
      "unit": "m",
      "desc": "门架抬升高度",
      "default": 1.5
    },
    {
      "id": "rotation_angle",
      "type": "number",
      "unit": "deg",
      "desc": "叉齿旋转角度",
      "default": 45
    }
  ],
  "steps": [
    {
      "id": "step_001",
      "joint": "_____10",
      "channel": "translate",
      "axis": "z",
      "t_start": 0,
      "t_end": 3,
      "value_start": "0",
      "value_end": "lift_height",
      "easing": "ease-in-out",
      "template_segment": 2,
      "template_segment_name": "lift"
    }
  ]
}
```

### 顶层字段

| 字段 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `template_meta` | object \| null | ⚠️ v6+ | 模板路径生成时的模板元数据。非模板路径为 `null` |
| `template_meta.kind` | string | ✅ | 模板种类：`forklift` / `threeway` |
| `template_meta.version` | number | — | 模板版本 |
| `template_meta.params` | object | — | 模板编译时用到的参数快照（诊断用） |
| `parameters[]` | array | ✅ | 参数声明 |
| `steps[]` | array | ✅ | 运动步骤 |

### parameters[] 字段

| 字段 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `id` | string | ✅ | 参数标识符（公式里引用），遵守 JS 标识符规则 |
| `type` | string | ✅ | 当前只支持 `"number"` |
| `unit` | string | — | 单位提示（`"m"` `"deg"` 等），仅用于显示 |
| `desc` | string | — | 参数描述 |
| `default` | number | ✅ | 默认值 |

### steps[] 字段

| 字段 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `id` | string | ✅ | 步骤唯一标识 |
| `joint` | string | ✅ | 关节 name（对应 joints.json definitions[].name） |
| `channel` | enum | ✅ | `"rotate"` / `"translate"`（与关节 type 对应） |
| `axis` | enum | ✅ | `x` / `y` / `z`（UI 坐标系） |
| `t_start` | number | ✅ | 步骤开始时间（秒） |
| `t_end` | number | ✅ | 步骤结束时间（秒） |
| `value_start` | string | ✅ | 起始值公式字符串 |
| `value_end` | string | ✅ | 结束值公式字符串 |
| `easing` | enum | — | `"linear"` / `"ease-in"` / `"ease-out"` / `"ease-in-out"`，默认 `linear` |
| `template_segment` | number \| absent | ⚠️ v7+ | 模板编译产出的段号（模板路径独有，诊断 / 轨迹 overlay 显示用）。非模板路径省略此字段 |
| `template_segment_name` | string \| absent | ⚠️ v7+ | 模板段名（如 `"approach"` / `"lift"`）。非模板路径省略此字段 |

### 公式语法

- 支持：数字、Math 函数（`Math.PI`、`Math.sin`...）、parameters 里定义的 id、四则运算、括号
- **禁止**：`;` `{` `}` `[` `]` `=` `"` 及任何非 Math 的标识符
- 示例：`"rotation_angle * Math.PI / 180"` / `"lift_height - 0.3"` / `"45"`
- 白名单机制：标识符必须在 parameters + Math 内，否则求值失败

### 关键约束

1. **已完成 step 保持 value_end**：`t >= t_end` 时 progress=1，不会 return（否则 PKF 循环会瞬跳，见 [CLAUDE #31](../../CLAUDE.md)）
2. **joint 必须匹配 joints.json 的 name**，模糊匹配 fallback 仅长度 > 3 且唯一命中才生效
3. **channel 必须和关节 type 对应**：`rotate` ↔ `revolute`，`translate` ↔ `prismatic`
4. **`template_segment` / `template_segment_name` 仅当非 null 时才写入 ZIP**（减小 ZIP 体积）。导入端用 `s.template_segment ?? null` 安全读取

## model.glb

GLTFExporter 序列化的当前场景。

### 约束

1. **零位态序列化**：导出前所有关节 currentValue 已归零（#20 修复）
2. **不导出 Scene 节点**：传 `sceneRoot.children` 过滤掉 Light/Camera/Helper（#12 修复）
3. **过滤轨迹 overlay**：UI toggle 的 `__isTrajectoryOverlay` 和 Console 诊断 `__isDiagTrajectory` 组都不烘焙进 GLB（F28 修复）
4. **embedImages: true**：纹理嵌入，不依赖外部资源
5. **binary: true**：输出 .glb 而非 .gltf

导入侧用 GLTFLoader 直接读取。

## 版本迁移

### v7 ← v6

- `joints.json` 新增 `limit_upper` + `overflow_to` 字段（双段门架 overflow 机制，bugfix #59）
- `pkf.json` steps 新增 `template_segment` + `template_segment_name` 字段（模板路径产出的诊断元数据，F61）
- **向后兼容**：老 ZIP 没有这些字段；导入端按 `?? null` 读取即可

### v6 ← v5

- `manifest.json` 新增 `scene_markers[]`（货物占位 / 取货点 / 放货点 metadata）
- 新增 `pkf.json` 文件（可选）
- `pkf.json` 新增 `template_meta` 字段

### v5 ← v4

- `motion.json` 的 `clips[]` 新增 `reparent_events[]`（在时间轴上切换对象 parent）
- `joints.json` 新增 `parent_name` 字段（跨 roundtrip 稳定）

### v4 ← v3

- `manifest.source` 新增 `root_name` 字段
- `model.glb` 由 GLTFExporter 重新序列化（v3 之前是原始文件副本）

**破坏性**：v3 的 `model.glb` 是原始 FBX/USD 副本，v4 的是序列化后的 GLB，层级可能不同。

### v3 ← v2

- `motion.json` 改为全局 clips schema（替代 per-object channels）
- `joints.json` 的 `origin` 改为 parent-local（v2 是世界坐标）

**破坏性**：v2 文件导入需要重新配置关节（origin 语义变了）。

### v2 ← v1

- `joints.json` 从关节点数据变为 FK 关节定义
- 删除 `joint-definitions.json`

**破坏性**：v1 文件不再支持自动迁移，导入会提示重配。

## 错误处理

### 后端 AI `/api/generate-pkf` 返回值

正常：
```json
{ "parameters": [...], "steps": [...] }
```

错误（role 匹配不上）— HTTP 422：
```json
{ "error": "当前模型没有'车体前进'角色的关节", "available_roles": ["门架升降", "叉齿旋转", ...] }
```

其他错误 — HTTP 500：
```json
{ "error": "AI 请求失败: <message>" }
```
