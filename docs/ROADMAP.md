# MotionForge 二期路线图

> 同事使用反馈整理（2026-04-17）。
> 这份不是承诺，是**已识别的方向**。优先级和时间表会随实际场景调整。
>
> 当前阶段：MotionForge v12+ 已 work，能做基础 AGV/叉车动画 + 取放货 + 自然语言生 PKF。
> 这份路线图列出"客户自己配"还需要补的能力。

---

## 反馈来源

同事用 MotionForge 一遍后说："比现在的配置简单一些，门槛低了，未来客户可以自己配"，但提了 5 个方向：

1. **辅助结构**（货物占位、停车取货方向、正方向）
2. **直观可视化**（占位/取货点/放货点的视口标记）
3. **货物大小参数**（夹抱式叉车的夹子根据货物宽度定位）
4. **复杂条件判断**（3 向 AGV 的方向分支）
5. **手动公式编辑**（80% AI + 20% 手工的兜底）

---

## 推荐执行顺序

| 顺序 | 项 | 工作量 | 价值 | 解锁什么 |
|---|---|---|---|---|
| 1 | **#5 手动公式编辑** | 0.5-1 天 | 立即兜底 AI 失败 | 用户对系统更有信心 |
| 2 | **#1 辅助结构** | 1-2 天 | 视觉清晰度大涨 | #2 #3 的基础 |
| 3 | **#2 取放货可视化** | 0.5 天 | 取放货流程一目了然 | L1 AI 更准 |
| 4 | **#3 货物大小参数** | 1-2 天 | 解锁夹抱式叉车 | 参数化机械的基础 |
| 5 | **#4 条件判断** | 3-5 天 | 解锁 80% 复杂动画 | 真正的"通用动画引擎" |

**总计**：6-10 天可以串起来做。建议分 4-5 周慢慢推。

## #1 辅助结构（货物占位 / 取货方向 / 正方向）

**是什么**：场景里加 3D 标记（不参与渲染逻辑，只做参考）：
- 货物占位：透明立方体，标"货物会在这"
- 取货方向：箭头，标"AGV 从这边接近"
- 正方向：箭头，标"AGV 自己的前方"

**怎么实现**：
- 新增 SceneMarker 概念（独立于 jointDef，只是 metadata + 视觉）
- UI：右键空白处或菜单"添加标记"
- 持久化：加到 schema v6，存 marker 列表（位置、类型、颜色、可选 size）
- 渲染：透明色 + 半透明文字标签

**工作量**：1-2 天。关键决策是 marker 数据存哪里——挂在 clip 还是 project 级（建议 project 级，所有 clip 共享）。

---

## #2 直观可视化（取货点 / 放货点）

**是什么**：基于 #1，但专门为"取放货流程"设计——取货点和放货点用不同颜色、能命名（"a"、"b"、"c"）、L1 AI 知道它们的位置。

**怎么实现**：
- 在 #1 的 marker 系统上加一个 `markerType: 'pickup' | 'drop' | 'waypoint'`
- L1 prompt context 里包含这些命名 marker
- "去 a 取货" 自动用 a 的世界坐标

**工作量**：0.5 天（基于 #1 之后）。和 L1 AI 高度协同。

---

## #3 货物大小参数

**是什么**：货物有 width/depth/height 参数。夹抱式叉车的夹子位置 = `width / 2 + offset`。

**怎么实现**：
- 货物 marker 加 `size: {w, d, h}` 字段
- PKF 公式可引用 `cargo.width` 这种变量
- 改 cargo 大小 → 视口立方体跟着变 + 公式重算 → 夹子动画自动调整

**工作量**：1-2 天。涉及 PKF 公式求值器扩展（允许引用 marker 属性）。

---

## #4 复杂多重条件判断

**是什么**：动画里加 if/else。3 向 AGV 例子：
- 货物在左 → 叉齿转 90°
- 货物在右 → 叉齿转 -90°
- 货物在前 → 叉齿伸出

**怎么实现**：
- PKF schema 加"条件 step"类型
- 条件表达式（同公式语法，结果是 bool）
- 运行时按时间到达条件 step → 求值条件 → 选分支
- UI 要表达分支结构（不能再是平铺列表）

**工作量**：3-5 天。**架构级改动**——PKF 从纯时间序列变成有条件逻辑。最复杂的一项。

---

## #5 手动公式编辑（兜底）

### 先解释什么是"公式"

MotionForge 里每个 PKF 步骤都有这两个字段：
- `value_start`：步骤开始时关节的值
- `value_end`：步骤结束时关节的值

中间会按时间在两者之间插值。

这两个字段**不是普通数字**，是**表达式字符串**。可以写：
- 纯数字：`"0"`、`"45"`、`"-90"`
- 引用 PKF 参数：`"lift_height"`、`"rotation_angle"`
- 数学运算：`"lift_height + 0.3"`、`"rotation_angle * 0.5"`
- Math 函数：`"Math.sin(0.5) * 2"`、`"Math.PI / 4"`
- 复合：`"safe_distance + cargo_width / 2"`

### 举个具体例子（夹抱式叉车）

```
PKF 参数：
  cargo_width: 0.6  (米，货物宽度)
  fork_offset: 0.05 (米，夹爪与货物之间留缝)

PKF 步骤：
  step1: 左夹爪关节 value_end = "-(cargo_width / 2 + fork_offset)"   → -0.35
  step2: 右夹爪关节 value_end = "cargo_width / 2 + fork_offset"     → +0.35
```

改了 `cargo_width` → 两个 step 自动重算 → 夹爪自动适配新货物。

### 现在的状态

PKF 步骤面板里**已经有公式输入框**（其实你能编辑），但：
- 没有语法提示，写错了不知道
- 公式求值失败时只在 console.warn 里报，UI 看不到
- 不知道改完会输出什么数（要等播放才知道）
- 没有常用模板能点选

### 怎么实现 #5

1. **实时校验**：输入框 onInput → 立刻试求值 → 红框 + 错误提示
2. **试算按钮**：旁边一个小按钮 → 输入当前参数值 → 显示求值结果（"用 cargo_width=0.6, 结果=0.35"）
3. **常用 snippet 下拉**：插入预设公式
   - `Math.sin(t * Math.PI)`（一个完整正弦周期）
   - `Math.PI / 2`（90 度）
   - `width / 2`（半宽偏移）
4. **公式语法提示卡片**：折叠区列可用变量、函数、运算符

**工作量**：0.5-1 天。**最快有反馈，风险最小**。

### 和"AI 生 PKF"的关系

- AI 一键生成可能 80% 对，剩下 20% 用户**手工调公式**
- 现在的痛点是"AI 错了我不会改"——#5 就是让"手工改"变得简单
- 类比：AI 是自动驾驶，#5 是方向盘

## 短期 vs 长期

| 时间 | 做什么 |
|---|---|
| **短期**（这周/下周可做） | #5 → 立刻能用 |
| **中期**（1-2 周） | #1 + #2 → 可视化层补齐 |
| **长期**（持续） | #3 + #4 → 真正"通用化" |

---

## 关键注意事项

- **#4 是分水岭**：做完之前，MotionForge 是"复杂动画编辑器"；做完之后，是"机械动画 DSL"。架构会从纯时间线变成时间线+条件树
- **#1 + #2 + #3 互相依赖**：marker 是基础，可视化是 marker 的 view，cargo size 是 marker 的扩展。建议合起来做
- **#5 是独立的，可以随时插队**：不依赖其他
